## 2. Детальный разбор реализуемости по каждому Use Case

### 2.1. UC_Register (Регистрация) и UC_Login (Авторизация)
* **Эскиз:** [docs/wireframes/auth_screen.svg](wireframes/auth_screen.svg)
* **Необходимые контролы:**
  - Поля ввода логина и пароля.
  - Кнопка отправки формы («Войти»).
  - Ссылка переключения в режим регистрации («Зарегистрироваться»).
* **Анализ реализуемости:**
  - Форма содержит все необходимые поля для ввода учетных данных.
  - При переключении на «Зарегистрироваться» форма дополняется полем «Имя пользователя» и отправляет запрос на создание учетной записи.
  - Ошибки (неверный пароль, дубликат логина) выводятся непосредственно под полями формы.

### 2.2. UC_Timer (Запуск и остановка секундомера в 1 клик)
* **Эскиз:** [docs/wireframes/timer_screen.svg](wireframes/timer_screen.svg)
* **Необходимые контролы:**
  - Выпадающий список выбора категории активности с цветовым маркером.
  - Крупный цифровой дисплей секундомера (`HH:MM:SS`).
  - Кнопки действий «СТАРТ» (зеленая) и «СТОП» (красная).
  - Информационный лейбл с бизнес-правилом минимальной длительности (1 минута).
* **Анализ реализуемости:**
  - Сценарий «в 1 клик» полностью обеспечен: пользователь выбирает категорию и нажимает «СТАРТ». Состояние кнопки переключается на активный секундомер.
  - При нажатии «СТОП» выполняется расчет длительности. Если прошло меньше 1 минуты, UI отображает toast/предупреждение о сбросе сессии без записи в историю, что полностью соответствует бизнес-правилу.

### 2.3. UC_Manual (Добавление записи времени вручную)
* **Эскиз:** [docs/wireframes/manual_record_screen.svg](wireframes/manual_record_screen.svg)
* **Необходимые контролы:**
  - Селектор категории активности.
  - Поля ввода даты и времени начала ($T_{start}$) и окончания ($T_{end}$).
  - Текстовая область для подробного описания активности.
  - Кнопка «Сохранить».
* **Анализ реализуемости:**
  - Форма ручного ввода скомпонована в левой части экрана. При вводе невалидного диапазона ($T_{start} \ge T_{end}$) или коллизии по времени с существующими записями система подсвечивает поля ошибки.
  - Правая панель экрана содержит таймлайн записей за день, позволяя пользователю визуально сопоставить вводимый интервал со свободными окнами времени.

### 2.4. UC_ManageOwnCategories и UC_ManageDefaultCategories (Категории)
* **Эскиз:** [docs/wireframes/categories_screen.svg](wireframes/categories_screen.svg)
* **Необходимые контролы:**
  - Форма создания категории: текстовое поле названия, ввод/выбор HEX-цвета с интерактивным превью кружка.
  - Чекбокс «Базовая категория (Admin)» — отображается и доступен только для акторов с ролью `ADMIN` (в правом верхнем углу отображается аватар `A`).
  - Список существующих категорий с бейджами `DEFAULT` (базовая) и `USER` (пользовательская), а также кнопками «Удалить».
* **Анализ реализуемости:**
  - Обычный пользователь создает личную категорию (флаг базы скрыт или заблокирован).
  - Администратор может создавать как базовые, так и пользовательские категории.
  - Список справа обеспечивает оперативный просмотр и удаление ненужных категорий.

### 2.5. UC_UpdateDesc, UC_ViewHistory, UC_RollbackDesc (История и откат описаний)
* **Эскиз:** [docs/wireframes/history_rollback_screen.svg](wireframes/history_rollback_screen.svg)
* **Необходимые контролы:**
  - Карточка текущего состояния записи с текстом актуального описания.
  - Хронологический список предыдущих версий описания с указанием автора/времени изменения и сохраненного текста.
  - Кнопка «Откатить» напротив каждой исторической версии.
* **Анализ реализуемости:**
  - Экран полностью закрывает весь жизненный цикл версионирования.
  - При нажатии на кнопку «Откатить» у выбранной версии UI инициирует вызов API отката, текущее состояние архивируется как новая версия, а текст выбранной версии становится актуальным в блоке «Текущая версия».

### 2.6. Просмотр аналитики и хронометража
* **Эскиз:** [docs/wireframes/manual_record_screen.svg](wireframes/manual_record_screen.svg) (правая колонка)
* **Необходимые контролы:**
  - Список зафиксированных интервалов с подсчетом длительности (например, «1 ч 30 мин»).
  - Цветовая полоса категории для быстрой визуальной группировки.
* **Анализ реализуемости:**
  - Позволяет отслеживать дневной хронометраж без перегрузки интерфейса сложными таблицами.

## 3. Заключение

Все 10 вариантов использования (Use Cases), описанных в диаграмме прецедентов и пользовательских сценариях WebLab#1, **на 100% реализуемы** с помощью спроектированного набора из 5 ключевых экранов (wireframes). Расположение элементов интуитивно понятно, соблюден баланс между простотой ввода (таймер в 1 клик) и расширенными возможностями (аудит описаний, ролевое управление категориями).
