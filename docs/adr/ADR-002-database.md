# ADR-002: Выбор архитектуры хранения данных для Web

## Статус
Принято

## Контекст
В проекте ППО использовалась локальная СУБД SQLite (Room) и ObjectBox. Для многопользовательского веб-приложения требуется выбрать СУБД для надежного серверного хранения записей, категорий и пользователей.

## Рассмотренные альтернативы
1. **SQLite (Room / File-based):**
   - *Плюсы:* Простота, уже используется в мобильном приложении и CLI.
   - *Минусы:* Блокировка файла БД при конкурентных записях, не подходит для серверного многопользовательского веб-бэкенда.
2. **MongoDB / NoSQL:**
   - *Плюсы:* Гибкая схема данных.
   - *Минусы:* Отсутствие декларативной ссылочной целостности (каскадное удаление версий и записей при удалении пользователя/категории), избыточность для строго реляционной модели данных.
3. **PostgreSQL (Выбранный вариант):**
   - *Плюсы:* Надежная промышленная реляционная СУБД, строгая поддержка ACID, развитая работа с внешними ключами и каскадами, стандарт для веб-разработки.
   - *Минусы:* Требует отдельного сервиса/контейнера для развертывания.

## Решение
Использовать **PostgreSQL** в качестве основной СУБД веб-бэкенда. Локальная SQLite сохраняется в качестве адаптера для легаси CLI и Android.

## Последствия
- Высокая надежность и параллельная обработка запросов пользователей.
- Четкое разделение сущностей БД, DTO и доменных моделей по Clean Architecture.
